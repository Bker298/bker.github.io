encryption_flow.exe

ثلاث مراحل أساسية: توليد المفاتيح، التشفير، وفك التشفير.

01

key_generation()

نختار عددين أوليين كبيرين p و q، ونحسب n = p × q، ثم نختار الأس العام e والأس الخاص d بحيث يكون (e × d − 1) قابلاً للقسمة على دالة أويلر φ(n).

n = p * q phi(n) = (p-1) * (q-1) 1 < e < phi(n), gcd(e, phi) = 1 d = e^(-1) mod phi(n)
02

encrypt(m)

لإرسال رسالة رقمية m، يرفعها المرسل للقوة e ويأخذ الباقي من قسمة n. النتيجة هي النص المشفر c.

c = m^e mod n
03

decrypt(c)

يستقبل المستلم c ويستخدم المفتاح الخاص d لاستعادة الرسالة الأصلية برفعها للقوة d وأخذ الباقي من n.

m = c^d mod n

crypto_math.mod

لماذا يعود (cᵈ) mod n إلى الرسالة الأصلية m؟ الجواب في نظرية فيرما الصغيرة ودالة أويلر.

∑

// why_it_works

لأننا اخترنا d بحيث e·d ≡ 1 mod φ(n). إذن cᵈ = (mᵉ)ᵈ = m^(ed) = m^(1+k·φ) = m · (m^φ)^k. وبموجب نظرية أويلر، m^φ(n) ≡ 1 mod n، فتصبح النتيجة m.

🛡️

// unbreakable

لإيجاد d من المفتاح العام (e,n) يجب معرفة φ(n) = (p−1)(q−1)، ما يعني تحليل n إلى عوامليه p و q. تحليل أعداد تصل إلى 617 رقمًا (2048 بت) يستغرق آلة حاسوبية آلاف السنين.

c = m^e mod n ==> m = c^d mod n

في التطبيقات الحقيقية تستخدم أعداد أولية ضخمة (2048 بت أو أكثر)، وهنا يعرض المثال أعداداً صغيرة لأغراض التعليم فقط.
